# Complex problems and how they were solved
- Logo lighting: the logo is a flat image, so the "metal catching light" effect uses two copies, a dim base and a bright copy revealed through a radial mask that follows the pointer. No libraries, works on touch.
- Strict CSP: no inline scripts or styles, so CSS and JS live in their own files.
- Order tampering: a store that inserts orders from the browser lets anyone set their own price. Orders go through the create_order SQL function, which reads prices from the products table and has no direct insert policy.
- Admin access: hiding the dashboard in the UI protects nothing. Every admin read and write is guarded by is_admin() in RLS, and uploads are limited to 3 MB JPG/PNG/WebP by both the form and the storage bucket.
- Stock and coupons under concurrent orders: create_order locks each product row (for update) before decrementing, so two customers can't both buy the last piece. Tracking needs the random code AND the phone number, so codes alone can't be guessed into someone's order.
- Receipt uploads without accounts: anonymous customers can upload to a private bucket, so it is limited to 2 MB images, folder names must look like an order code, and only attach_receipt (code + phone + path prefix must all match) links a file to an order. Anyone can still upload junk files, so there is no rate limit yet; watch storage usage.
- Secrets: Cloudinary secret and Telegram token only exist as Supabase secrets in Edge Functions. The upload signature also pins allowed formats, and the function refuses anyone who is not in the admins table. The webhook function rejects calls without the shared secret header.
- Unstyled page in dev: a strict style-src CSP blocks the inline <style> tags Vite injects in dev mode (and its inline hot-reload script). Fix: add the CSP meta only at build time, where CSS is an external file. Test the CSP with npm run build && npm run preview before launch.
- Empty sections: a store with no photos or reviews looks broken or fake. Lookbook, reviews, FAQ and size chart stay hidden or show a 'coming soon' note until real content is added in the dashboard, and no placeholder measurements or reviews are invented.
- Glass with cut corners: backdrop-filter must sit on the same element as the clip-path (a clipped parent becomes a backdrop root and blurs nothing). The 1px border follows the diagonal cuts by clipping a gradient pseudo-element with an even-odd polygon (outer shape minus inner shape).
- Flat dark look: pure black with grey text felt lifeless. Fixed with cool ambient glows, fine grain, a light silver band for contrast, scroll reveals and a pulsing glow behind the logo.
- Dashboard styles leaking: the storefront has global input and class styles, so every dashboard class is prefixed ad- and form controls are re-styled inside .ad-root. Checkboxes need an explicit size because the global input rule is width:100%.
- Phone layout: hover-only features (logo light, second product photo) have touch equivalents. touch-action:none on the logo trapped scrolling, so it is pan-y now. The 3-column header overflowed narrow phones until the grid children got min-width:0 and the header shrank below 600px. Vite env vars are build-time: after adding them on Vercel you must redeploy.
- Arabic page wider than the screen: grid items default to min-width:auto, so one wide child stretched the whole column and the max-width:600px rules stopped matching. Fixed with minmax(0,1fr), a clipped hero, html overflow-x:hidden (not on body, which would break the sticky header) and mobile rules up to 899px.
- Reviews you can trust: the token is random and stored per order, the RPCs only accept shipped or delivered orders, and a unique order_id means one review per order. Reviews start as pending so abusive text never goes live by itself.
- Non-technical editing: delimiter formats (Question || Answer, comma lists, S:10) were replaced with structured editors. Settings store JSON (arrays and objects) instead of text, and the storefront reads those shapes.
- Google and hash links: crawlers ignore everything after #, and WhatsApp/Facebook never run JavaScript. Fix: real paths, a Vercel function that returns index.html with the page's own head tags, and the same tags re-applied in the browser. Language lives in the URL (/ar) so each language has its own indexable page with hreflang. Vite env values are build-time, so VITE_SITE_URL needs a redeploy.
- Analytics and private links: review URLs contain a secret token, so the analytics script drops events for /admin and /review before sending. Vercel Hobby is for non-commercial use per Vercel's docs, so a real shop needs a plan that allows commercial use.
- Own analytics without invading privacy: no IP or persistent id is stored. Country comes from Vercel's request header inside api/track.js, visits are grouped by a random session code kept in sessionStorage, writes go only through a validating function with a flood guard (300 rows per minute), and reads need an admin. Counts are approximate.
- Keyboard disappearing in dialogs: an effect with onClose in its dependency list re-ran on each keystroke and called focus() on the dialog, stealing focus from the input. Fixed by focusing once on open and keeping the latest onClose in a ref.
- Placeholder products: the store fell back to three demo products whenever the catalog was empty or failed to load, and customers could add them to the cart although checkout rejects unknown products. They now only appear when running locally without Supabase keys.
- Checkout button 'not working': a disabled button with no explanation looks broken, and the phone regex only accepted ASCII digits, so Arabic keyboards could never pass it. Now the button stays active, validates on click, focuses the first bad field, accepts Arabic digits and shows the server's reason.
- Save button missing in iPhone dialogs: viewport-fit=cover let Safari's bottom bar cover fixed bottom elements and 100vh is taller than the visible area. Dialogs now size to visualViewport (follows the keyboard) and dvh.
- Dialog taller than the screen: percentage max-height on a grid item resolves against a row that grows with its content, so nothing was limited. Use flex plus a --ad-vh pixel value from visualViewport. Keep one dialog component for every form so the fix applies everywhere.
- Review link 'invalid': a confirmed (not yet shipped) order correctly cannot be reviewed, but the page gave one vague message for every case and the order dialog closed after saving. Added specific messages and kept the dialog open. A missing database function is reported as a technical error instead of an invalid link.
